# Ванлав Сайты

Сайт студии разработки сайтов: сайты с нуля на заказ + каталог готовых решений. Next.js 16 (App Router) + TypeScript + three.js. Все страницы статические (SSG), единственный серверный код — `/api/lead` (заявки в Telegram).

## Запуск локально

```bash
npm install
npm run dev        # http://localhost:3000
npm run build      # проверка продакшн-сборки
```

## Выкладка на Vercel

**Вариант 1 — через GitHub (рекомендуется):**
1. Создайте репозиторий на GitHub и запушьте эту папку (`git remote add origin … && git push -u origin main`).
2. На vercel.com → Add New → Project → выберите репозиторий. Framework определится сам (Next.js), настройки менять не нужно → Deploy.

**Вариант 2 — через CLI:**
```bash
npm i -g vercel
vercel          # превью
vercel --prod   # продакшн
```

### Заявки в Telegram (необязательно)
В Vercel → Project → Settings → Environment Variables добавьте:
- `TELEGRAM_BOT_TOKEN` — токен бота от @BotFather
- `TELEGRAM_CHAT_ID` — ваш chat id (напишите боту, затем откройте `https://api.telegram.org/bot<TOKEN>/getUpdates` и возьмите `chat.id`)

После этого сделайте Redeploy. Пока переменные не заданы, форма работает как в прототипе: открывает Telegram @h4r4dex с готовым текстом заявки.

Опционально `NEXT_PUBLIC_SITE_URL=https://ваш-домен.ru` — для sitemap и OG-ссылок (на Vercel без него берётся продакшн-домен проекта).

## Где что менять

Всё содержимое — в `lib/data.ts`: контакты, данные автора (в т.ч. фото), цены, услуги, шаблоны.

### Как заменить заглушку шаблона на готовый сайт
1. Сделайте скриншот сайта шириной 1280px (первые ~2000px высоты — они же крутятся на экране ноутбука в hero) и положите в `public/sites/<id>.jpg`.
2. В `lib/data.ts` у нужного шаблона заполните:
   - `image: '/sites/<id>.jpg'`
   - `demoUrl: 'https://…'` — ссылка на живой сайт
   - `domain: '…'` — домен в рамке браузера
   - при желании `title`, `description`, `tagline`, `niche`.
3. Готово: карточка в каталоге, 3D-витрина, страница шаблона и ноутбук на главной сами подхватят скриншот, «Посмотреть демо» откроет живой сайт, появится метка «Живой сайт».

Пример — шаблон `napor` (https://napor-landing.vercel.app/).

### Фото автора
Положите фото в `public/author.jpg` и в `lib/data.ts` → `AUTHOR.photo: '/author.jpg'`.

## Структура
- `app/page.tsx` — главная (порядок секций)
- `app/templates/[id]` — страница шаблона, `…/demo` — встроенное демо макета
- `app/api/lead/route.ts` — отправка заявок в Telegram (honeypot + лимит 5 заявок / 10 мин с IP)
- `components/*` — секции
- `lib/devices3d.js` — 3D-сцены (ноутбук в hero, планшет/телефон/ноутбук в «Автоматизации»)
- `app/globals.css` — все стили и дизайн-токены

## SEO

Что уже сделано в коде:
- **Мета-теги** на каждой странице: уникальные title/description под запросы, canonical, Open Graph и Twitter-карточки (картинка `public/og.png`).
- **Посадочные страницы услуг** `/uslugi/<slug>` — отдельная страница под каждый запрос («создание лендинга», «сайт-визитка», «разработка Telegram-бота» и т.д.) + хаб `/uslugi`. Тексты — в `lib/services-content.ts`.
- **Микроразметка Schema.org (JSON-LD)**: организация (ProfessionalService/LocalBusiness) с каталогом услуг и ценами, WebSite, FAQPage (главная и страницы услуг — даёт расширенные сниппеты), BreadcrumbList, Service/Offer на страницах услуг и шаблонов, ItemList каталога.
- **Блок FAQ** на главной и на страницах услуг.
- **sitemap.xml** (с картинками), **robots.txt**, **manifest**, фавиконки для всех устройств.
- **Скорость**: шрифты раздаются со своего домена (без Google Fonts), скриншоты через `next/image` (WebP/AVIF, нужный размер), 3D грузится лениво.
- **Перелинковка**: услуги ↔ страницы услуг ↔ шаблоны ↔ подвал.
- Демо-страницы закрыты от индексации.

Что сделать тебе после деплоя (без этого поисковики будут индексировать медленно):
1. **Свой домен** (например `vanlav.ru`) → Vercel → Settings → Domains. В `NEXT_PUBLIC_SITE_URL` указать его.
2. **Яндекс Вебмастер** (webmaster.yandex.ru): добавить сайт → способ «Мета-тег» → значение `content` в `NEXT_PUBLIC_YANDEX_VERIFICATION` → Redeploy → подтвердить. Затем: «Индексирование → Файлы Sitemap» → `https://домен/sitemap.xml`; «Региональность» → Сочи; «Переобход страниц» → отправить главную и /uslugi/*.
3. **Яндекс Метрика** (metrika.yandex.ru): создать счётчик → номер в `NEXT_PUBLIC_YM_ID` → Redeploy. Настроить цели: отправка формы, клик по Telegram.
4. **Google Search Console**: то же через мета-тег → `NEXT_PUBLIC_GOOGLE_VERIFICATION`, добавить sitemap.
5. **Яндекс Бизнес** (business.yandex.ru): создать карточку организации «Ванлав — студия разработки сайтов», Сочи, сайт + Telegram. Это сильно помогает в локальной выдаче и на Картах.
6. **2ГИС** и **Google Business Profile** — такие же карточки.
7. Собирать **отзывы** в Яндекс Картах/2ГИС и **ссылки** на сайт: подпись в портфолио на Kwork/Хабр Фрилансе/VC, соцсети, футер сайтов клиентов («Разработка — Ванлав»).
8. Регулярно добавлять новые **работы в каталог** и расширять тексты страниц услуг — поисковики любят обновляемые сайты.

## Производительность и адаптив

- **3D-сцены** (ноутбук, планшет, телефон) стартуют только после первого действия пользователя (скролл, касание, движение мыши) и когда браузер свободен. До этого показывается лёгкий WebP-постер (`public/brand/*-poster*.webp`). На телефонах и слабых устройствах работает облегчённый режим: без теней, меньше текстуры, 30 fps. При «экономии трафика», «уменьшении движения» или без WebGL остаётся постер.
- **Шрифты** лежат в `public/fonts` (`app/fonts.css`): только кириллица и латиница, ключевые файлы грузятся с preload. Запасной шрифт подогнан по метрикам, поэтому вёрстка не прыгает при загрузке (CLS = 0).
- **Картинки** отдаются через `next/image` (AVIF/WebP нужного размера). Макеты шаблонов-заглушек в карточках заранее отрендерены в WebP (`public/sites/mock`), скриншоты для экрана ноутбука тоже лежат рядом в WebP.
- **Ленивый рендер** секций ниже первого экрана (`content-visibility`). После загрузки и при переходе по якорю секции дорендериваются, чтобы якоря попадали точно.
- **Мобильные**: горизонтальная прокрутка исключена (`overflow-x: clip` + проверка всех секций на ширинах 320–1920), прокрутка страницы блокируется при открытом меню, `svh` вместо `100vh`, нет автозума полей в iOS, hover-эффекты отключены на тач-экранах, учтены safe-area.

Обновить картинки-превью заглушек и WebP скриншотов после изменений в `lib/data.ts`:
```bash
npm run build && npm start      # в одном окне
npm run previews                # в другом (нужен установленный Chrome или CHROME_PATH)
```

## Скриншоты живых сайтов

Скриншоты, снятые «внахлёст», склеиваются без дублей и разрывов скриптом:

```bash
python3 scripts/stitch.py <id> <высота_шапки_px> кадр1.png кадр2.png …   # → public/sites/<id>/full.jpg, cover.jpg
npm run slices                                                          # кадры для экрана 3D-ноутбука
```

Скрипт печатает `imageH` и `coverH` — их нужно вписать в `lib/data.ts`.
